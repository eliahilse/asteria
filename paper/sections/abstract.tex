\begin{abstract}
We study whether automatically acquired repository security context improves
code produced by a large language model for a Java highscore feature, using
generation and code reuse. Across two rounds of 80 trajectories each, all tested
security-context strategies show fewer total failed security checks than matched
controls, including under conservative treatment of unresolved outcomes. However,
functional repair remains costly, and improvements in handling large inputs vary
across context acquisitions. These exploratory results support targeted
improvements on the tested task; they do not establish that the implementations
are secure or that the findings generalize across repositories.
\end{abstract}
