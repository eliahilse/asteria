\begin{abstract}
We ask whether a repository-specific \emph{security context}, a document
of assets, trust boundaries, weakness types, requirements and controls
written by an agent from the repository and a one-line feature
description, makes LLM-generated code more secure, and what it costs.
Task: a Highscore feature for a Java game, implemented from scratch
(Generation) or by reusing a sibling game's implementation (Reuse) by
OpenAI's \texttt{gpt-5.6-luna} at reasoning effort high, scored by ten
security checks and sixteen functional tests against a control collected
alongside. Three ways of writing the document (high-level guidance from
the repository, a full document anchored to code, a generic document
written without any repository) are compared under one response and
under agentic delivery with repository tools and feedback. Compiled
artifacts without context pass 22\% (one response) and 33\% (agentic) of
the security checks; with any of the three documents 82 to 90\%, within
five points of each other in each mode, at unchanged test pass rates. A
judge that cancels violating submissions adds nothing at 1.4 times the
tokens. On a second, harder task (Achievements) nothing compiles under
one response, and with tools and feedback the document takes compiled
artifacts from 78 to 95\% of the checks and half of them to passing every
test and check, while the judge costs attempts. Two tasks, one pair of
games and ten artifacts per arm limit what the rates can claim.
\end{abstract}
