\section{Discussion}
\label{sec:discussion}

The document is what matters. Any of the three agent-written documents
takes the security checks passed by compiled artifacts from 22 to 33\% to
82 to 90\%, in both delivery modes, with the three strategies within five
points of each other; the one written without any repository does as well
as the one anchored to code. Functionality does not pay for it: with
feedback every artifact compiles and passes the tests with or without a
document, and under one response the loss is delivery, which the document
does not worsen. Neither addition to the agentic harness earned its cost:
the judge, constrained to one cancellation per trajectory with a verbatim
quote, leaves the rate where it is at 1.4 times the tokens, and the code
graph of what the model reads (in the repository's rounds I26 to I28)
changes nothing. What remains failed is the resource pair, and its
history is the study's second finding: the agent follows its document
literally, so the wording of one instruction to the acquisition agent
decided in turn the record bound, the sign of a score, the blank name
and, unsuccessfully, the length of a line (versions 11 to 13, each
removing the failures its predecessor left open; the third named the
bound and the artifacts applied it after the read). Rounds before
version 13, including researcher-written context and the earlier
instruction versions, are documented in the repository and are not
pooled with these results.

\paragraph{Threats to validity.}
One task, one pair of games, one model as agent, generator and judge.
Each arm shares one acquired document across its ten artifacts, so the
artifacts measure generation variability given that document, not
acquisition variability; the repository holds repeated acquisitions for
an earlier instruction version. The five input-policy checks weigh
heavily in the ten. The million-record check is unresolved when the
audit cannot write the artifact's file format, and counts as not passed.
The provider served a different model for some responses; those
trajectories stopped before any evaluated submission and were collected
again under a declared rule. Artifact reviews are single-pass model
judgements with cited lines. The agent's instructions were revised after
examining failures on this same task, so they show that the rule can be
written, not that it transfers to another feature or repository.

\section{Conclusions and Future Work}
\label{sec:conclusions}

Repository-specific security context, written by an agent and given to
the model before it writes, raises the share of security checks a
compiled artifact passes from a quarter or a third to well over four
fifths, without a functional cost, under one response and under agentic
delivery alike; how the document is acquired matters less than that it
states its bounds and domains as numbers, because the generator follows
it literally. Enforcement during the attempts, by a judge or by extra
code context, did not add to what the document achieves. Next steps
follow from that: a second feature and repository to test whether the
instructions transfer, an evaluation whose preconditions do not depend
on the artifact's file format, and acquisitions repeated per task
variant so that the document, not the draw, is what a comparison
measures.
