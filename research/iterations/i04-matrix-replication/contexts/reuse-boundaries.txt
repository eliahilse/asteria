Security context for the requested highscore feature: ApoIcarus provides a singleton in-memory highscore with parallel name/time/points lists and network POST/GET persistence. Its save path URL-encodes the score, time, and player name but sends them to a remote endpoint; its load path parses an unbounded line stream in repeating point/time/name groups directly into integer lists. ApoMario's indexed source has no inspected highscore implementation or matching search hits. ApoMarioLevel owns level time and player state; player points are mutable and are incremented for coins and finish outcomes, so run-end recording must occur after the terminal scoring logic and before the level/player state is discarded. The required integration must add a file-backed board, a dedicated menu view/panel, and a call at both clearing and losing terminal paths. Storage input is a file Path and player name is user-controlled; persistence and rendering should treat both as untrusted data. Preserve list alignment, validate decoded record counts/types/ranges, bound file size and record count, use safe character/length handling for names, avoid remote/network submission, and use atomic replacement or otherwise failure-safe writes. Survival time is required in milliseconds and only formatted as mm:ss at display time; avoid integer overflow when converting or calculating elapsed duration. The target repository is an indexed JAR snapshot, so edits to embedded source may require corresponding build/source integration not visible in the snapshot.
