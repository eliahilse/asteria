# I04: repeat and extend the selected paper-context matrix

This schedule was declared during I03 collection in the iteration index. It
includes all four paper-context cells selected by the completed original replay:
Generation S, Generation S+F+B, Reuse B and Reuse S+B. Each receives no security
insert, an overview, requirements or trust-boundary guidance, with five fresh
trajectories per combination: **80 trajectories**, at most three submissions each.

The code protocol, v3 evaluator, model request settings, repository inputs and
context acquisition protocol are unchanged from I03. All six context acquisitions
are new conversations using only repository source and the relevant task; no I03
context or generated code is supplied. Fresh control responses are collected for
every cell. Overview remains included despite its weaker I03 results.

The first two repeated cells (Generation S+F+B and Reuse B) test whether I03's
descriptive tendency appears with fresh contexts and responses. Generation S and
Reuse S+B extend paper-context coverage and are reported separately. Each acquired
insert is shared across its method's two paper-context cells and repetitions;
these are not independent context samples. This remains a study of one feature
and game, with two rounds of context acquisition rather than broad generalization.

Every submission and failed acquisition is retained. The fixed schedule completes
regardless of outcomes. Code feedback includes delivery/compiler/functional
diagnostics only, with no security feedback. All 16 functional and 11 security
test contracts stay frozen; no source repair occurs during evaluation beyond the
already documented author integration/package/import procedure.

Primary reporting retains first-submission and within-budget functional success
with the full trajectory denominator. Security reporting includes every declared
check's failed, evaluated and unresolved counts, plus conservative count bounds.
The positive persistence round trip is separate from issue counts. The complete
task, source hashes, prompt hashes and acquisition provenance are in `plan.json`;
literal inserted texts are in `contexts/`.

I03's complete raw evidence, results and workbook were committed and externally
verified before beginning I04. I04 receives the same preservation before another
iteration starts. Effective provider settings remain unverified when unattested;
returned model identity is required to match Luna.
