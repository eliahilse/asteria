Security context for integrating persistent highscores. The inspected game exposes level elapsed-time state as an integer: getPassedTime() returns random-level time minus remaining time (E0009), while the HUD currently renders level.getTime() through a helper (E0003). Player points are mutable and retrieved through ApoMarioPlayer.getPoints() (E0013); points are awarded in multiple end-of-run paths, including finish/time/difficulty/width and win-against-another adjustments (E0009, E0015–E0031), so recording must occur only after the final scoring transition. Player display identity is currently derived from teamName, with null falling back to human/AI labels (E0034–E0046); there is no inspected dedicated player-name API. Menu and game are separate model panels (E0010–E0012), and run completion sets the component win state (E0060). No highscore implementation or persistence format was inspected; the provided class/member contract and exact lifecycle integration remain implementation obligations, not repository facts.
