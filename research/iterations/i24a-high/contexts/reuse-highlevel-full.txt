Add a local, persistent highscore store, a finished-run recording step, and a dedicated menu panel. Reuse ApoIcarus’s record model, sorting, formatting, and panel-navigation concepts while adapting persistence to the supplied file path and ApoMario’s level lifecycle.

Assets:
- Highscore records and ranking [integrity]
- Player names associated with completed runs [authenticity]
- Persisted highscore file [availability]
- Highscore menu presentation [integrity]

Trust boundaries:
- Local highscore file [entry point]: User-editable bytes representing stored names, scores, and survival times from The file supplied to the highscore store to Highscore parsing and in-memory record construction
- Finished level state [entry point]: Score, player identity, and elapsed time derived from a level affected by local or shared level content and cheating from The level-end recording integration to The operation that receives a completed run
- Player-name input [entry point]: A locally entered or edited display name from The run-completion name-entry flow to The operation that receives a new highscore record
