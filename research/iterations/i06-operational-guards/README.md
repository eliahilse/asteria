# I06: explicit operational security guards

Declared during I05 collection, before any operational-context acquisition.
I03/I04 showed that favorable totals can coexist with resource failures and
unchanged counts of affected artifacts. I06 investigates a more explicit context
representation: **operation, untrusted input, invariant, enforcement point and
failure behavior** for each proposed safeguard. Guard ordering and resource units
are part of the acquisition instruction; fixture sizes and thresholds are not.

Two new Luna acquisitions start from the Generation/Reuse repository snapshots
and Highscore task only. They retain the v3 evidence-ID and basis rules but add
five structured fields. Recommendations and change risks require all five;
unknowns may leave fields unset. Field completion validates structure, not truth
or implementation correctness. Repository/task evidence must justify claims;
policy choices and missing information remain explicit. Acquisition has 16 turns,
including finish, and receives no earlier code, contexts, audits or tests.

After I05 is completed and preserved, freeze **four paper-context cells × four
arms × five trajectories = 80 fresh trajectories**, at most five submissions each.
The arms are no security context, requirements, trust boundaries and operational
guards. The first three reuse I04/I05 prompt bytes exactly; the operational arm
appends its new insert to the matching no-security prompt. Overview is replaced
prospectively because I03/I04 did not show a consistent benefit. Its earlier
results remain retained and reported.

The edit protocol, model request settings, v3 evaluator and all test contracts
remain unchanged. Full functional success, first-submission success and repair
curves use every scheduled trajectory. Resource-stress outcomes and affected
trajectory counts are the primary security diagnosis for this exploratory round;
input/retention policies and the full ten-check total remain separate. Apply the
frozen large-record qualification audit to every final compiled artifact after
collection. Security outcomes never enter code-generation feedback.

This is strategy development, not a confirmatory formatting experiment. The new
instruction, generated content, representation and length vary together. One
operational acquisition per method is shared by ten code trajectories; this is
not ten independent context replications. Complete the fixed schedule regardless
of direction. Preserve failed acquisitions, every edit attempt and all negative
results, with a verified external copy before any subsequent iteration.
