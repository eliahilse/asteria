At the gameplay integration point, missing or invalid values must be normalized to stated safe defaults before those operations are called so valid gameplay effects still occur.
Task relevance: Protects threshold evaluation and stored unlock integrity while preserving achievement processing during malformed inputs.
Failure behavior: The receiving operation reports and rejects invalid input; the caller normalizes missing or invalid integration values to zero before calling it.
Basis: prospective task requirement or reasoning; not an implemented safeguard.

[R2; requirement; task; information_disclosure; CWE-502; CWE-20; CWE-400; CAPEC-150; CAPEC-153; V5.5.1; V14.2.1] The achievement store must be treated as untrusted structured data, parsed without Java object deserialization or executable interpretation, and each file, line, record, field, identifier, and numeric value must be bounded before retention: at most 64 KiB per file, 4 KiB per line, 256 records, 64-character identifiers, and 32 characters per numeric field.
Task relevance: Limits local-file attack surface and prevents achievement data from becoming code execution.
Failure behavior: The parser rejects and reports malformed, oversized, or unsupported data; valid records within bounds are retained, and excess retained records are evicted rather than causing valid input rejection.
Basis: prospective task requirement or reasoning; not an implemented safeguard.

Failure behavior: The store operation reports the rejection and returns recoverable state; its caller substitutes an empty set before displaying or continuing persistence.
Basis: prospective task requirement or reasoning; not an implemented safeguard.
